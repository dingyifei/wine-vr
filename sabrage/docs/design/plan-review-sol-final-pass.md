# Sabrage plan review — 5.6-sol final pass

(Generated via claudish `run_prompt` — claudish session mode fails at spawn on this machine, so the model reviewed the plan text + a verbatim evidence block inline and this file was saved on its behalf. Review target: ~/.claude/plans/i-m-thinking-we-should-parallel-diffie.md after the F#/S# revision rounds.)

Blocker findings: none.

1. [SEVERITY: major] STATIC `cfg.protocol` GATE CANNOT REPRESENT SHELL BEHAVIOR — The declared `cfg.protocol shell-warn/native-block` split loses a shell blocking case. The evidence says `alvr` is accepted, `oxrsys` warns, and every other protocol dies; one static shell gate of `warn` therefore misclassifies unsupported values and can let tier-1 report parity while native and shell launch eligibility differ. Split this into value-specific checks, such as `cfg.protocol.supported` with block/block and `cfg.protocol.legacy-oxrsys` with warn/block, or extend the schema to map evaluator outcomes to gates; add fixtures for `alvr`, `oxrsys`, and an unknown value.

2. [SEVERITY: major] DETACHED SESSION RECONCILIATION DOES NOT DEFINE THE ALREADY-DEAD CASE — The plan specifies reconciliation to "Re-attach … or Stop," but a detached wine session may terminate while Sabrage is absent. Evidence shows launch mutates host audio and relies on EXIT teardown to restore it; after detach, guards are deliberately disarmed, so a naturally exited session can leave BlackHole/audio volume and other reversible state pending until relaunch. On relaunch there is then nothing to reattach to or stop. Define an explicit reconciliation state machine for Live, Dead, and IdentityMismatch: Dead must run persisted reversible guards idempotently before allowing another launch; IdentityMismatch must never signal the reused PID and must apply only independently safe restoration; persist per-guard completion atomically and test detach→game exits→app relaunch.

3. [SEVERITY: minor] SHELL CHECK COVERAGE USES SET EQUALITY AND CANNOT DETECT DUPLICATE TAGS — Tier-1 asserts that the shell tag set equals `{shell_gate != none}`, which detects missing and unknown slugs but not a duplicated `# preflight:`/`chk` call. This is weaker than the native registry's explicit duplicate-binding rejection and could execute a side-effecting or costly shell check twice without failing parity. Compare slug cardinalities rather than sets, require exactly one call site unless a contract entry explicitly declares repetition, and retain ordered-sequence comparison for launch actions.

4. [SEVERITY: minor] CONCURRENT AGENT OWNERSHIP EXCLUDES SHARED GENERATED FILES — "Disjoint-file ownership" and worktree isolation only for same-crate concurrency do not protect workspace-wide files. Phase 1 runs tests, CLI, and screen work in parallel, while Rust dependency changes can all rewrite the shared `Cargo.lock`; formatters, contract generation, Tauri generation, and npm tooling can likewise touch files outside an agent's nominal module. The evidence also establishes linked worktrees and sibling-agent worktrees, so this is an available rather than hypothetical control. Either isolate every concurrent code-writing agent in a worktree and reconcile centrally, or prohibit agents from updating lockfiles/generated outputs and serialize one designated integration agent for dependency, regeneration, formatting, and commits.

Verdict: do not ship the plan unchanged. There are no remaining blockers, and most earlier factual/parity issues appear coherently addressed, but the protocol gate model and dead-detached-session recovery need specification before implementation because both affect launch safety and parity semantics. After those fixes, the remaining risks are enforcement robustness around duplicate shell bindings and concurrent agent mutation of shared workspace artifacts.
