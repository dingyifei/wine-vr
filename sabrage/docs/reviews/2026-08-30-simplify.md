## Efficiency findings — Sabrage (`dingyifei/gui`)

**1. `sabrage/crates/sabrage-core/src/process.rs:462`, `:512`, `:559`; `sabrage/crates/sabrage-core/src/fixes/backend.rs:161` — every process probe walks the entire process table, and `ProcInfo::observe` does it while documenting that it doesn't.**
`System::new_with_specifics(RefreshKind::nothing().with_processes(k))` is not a cheap constructor: `refresh_specifics` (sysinfo-0.39.6 `src/common/system.rs:112-121`) calls `refresh_processes_specifics(ProcessesToUpdate::All, true, k)` internally — I read the source to confirm. So `observe`'s doc ("Refreshes exactly that pid rather than the whole table") is inverted: it walks **all 1346 processes** on this machine with `proc_pidpath` before the 1-pid refresh it wanted. `find_processes_by_exe`/`by_cmdline` then walk twice (constructor + their own explicit `All`), and `by_cmdline` reads all 1346 argv regions twice via `KERN_PROCARGS2`. `backend.rs:161-162` does the same with `with_environ`, reading 1346 full environments twice — under a comment claiming it avoids "a second full process scan". The amplifier: `commands.rs:954` polls `snapshot()` at 1 Hz, which calls `is_same_process()` → `observe()` whenever a session is live or persisted, i.e. for the entire duration of a Beat Saber session. ≈1346 `proc_pidpath` calls **per second** while the user is playing.
**Cheaper:** `System::new()` at all four sites. It is a genuine no-op constructor; the `ProcessesToUpdate::Some`/`All` refresh that follows already does the right thing. ~1346× for `observe`, exactly 2× for the others — four one-line changes.

**2. `sabrage/src-tauri/src/commands.rs:953-966` + `sabrage/ui/src/stores/session.svelte.ts:176-178` — the 1 Hz broadcast is unconditional, and the dedup its comment delegates to does not exist.**
The Rust doc at `:941-944` says it emits unconditionally because "the frontend store is the one that dedups". The store is `onSessionStatus((s) => { status = s; })` — an unconditional assignment of a freshly deserialized object. Cost: 86,400 ticks/day of `state::load` + `runtime_status.json` read + 2 JSON parses + 1 serialize + IPC + a webview re-render of every `status` reader (sidebar dot, Session pill, Library rows, EditGame), producing an identical `{"phase":"idle",…}` at complete idle.
**Cheaper:** `SessionStatus` already derives `PartialEq` (`session/mod.rs:107`) — hold the last emitted value and skip the `emit` when equal. Fixes both the IPC and the app-wide 1 Hz render churn in one place.

**3. `sabrage/crates/sabrage-core/src/stages/stop.rs:277` and `:366` (from `:156`, `:165`) — one `stop` performs 3 independent full-table scans.** With finding 1 that is **6 complete walks per `./sabrage stop`**, ≈8000 `update_process` calls and ≈2690 `canonicalize()` syscalls (`find_processes_by_exe` canonicalizes *every* process's exe, not just candidates). **Cheaper:** one scan with `with_exe + with_cmd` that partitions against a `&[Needle]` slice, or take one snapshot in `stop::run` and pass it to `report_survivors` and both `reap` calls.

**4. `sabrage/crates/sabrage-core/src/process.rs:412` — the output pump clones every child output chunk into a tail ring that the caller usually throws away.** `emit` does `t.push_back(chunk.clone())` under a shared `std::sync::Mutex`, plus `step: step.to_string()` — a fresh `String` per chunk for what is already a `&'static str` `StepId`. `spawn_streamed:253` discards the tail outright (`let (status, _tail)`); only `run_ok`'s non-zero-exit branch (`:266-275`) reads it.
